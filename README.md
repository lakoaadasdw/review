# apiflow · 接口 × 方法调用链审阅

在浏览器里点一下页面按钮，就能看到这条链路：
**点击元素 → 事件处理 → HTTP 请求 → HTTP 响应 → 后端 Controller → 方法内调用的每个方法**。

后端部分以「源码卡片」呈现：每个方法展示完整代码，**方法里哪一行调用了别的方法，就从那一行拉一条线**接到被调方法的完整源码卡片；异常链路整条变红，并标出**最早失败的根因**。用于人工快速审阅、定位 bug。

当前版本：v0.21（调用图 + 源码卡片 + 重复请求折叠 + 自由拖动 + 缩放 + 多接口分组与折叠 + 响应体 JSON 树 + MyBatis XML 映射 + 异常根因标记 + 接口层失败隐藏方法链 + 前端调用链 + 流向高光 + **多语言适配器**：`graph-core` 语言无关图逻辑 + `adapters/java`、`adapters/python`，`--lang auto|java|python` 自动识别；Python 走 stdlib `ast` 静态解析，Python 见 `docs/screenshot-python.png`）。

## 它是怎么拿到数据的

| 环节 | 数据来源 |
| --- | --- |
| 点击 / 事件处理 | 往目标页面注入探针（`src/probe.js`），包装 `addEventListener`、`fetch`、XHR、`window.onerror` |
| HTTP 请求 / 响应 | 探针给请求打 `x-apiflow-trace` 头，浏览器侧 CDP 拿状态码、耗时、响应体摘要 |
| 后端 Controller / 方法调用图 | **静态解析**后端源码（`src/adapters/*`），带每个方法的完整源码与调用点行号；不要求后端运行。Java：`java-routes.mjs` 正则硬扫；Python：`python -X utf8 src/py/ast_dump.py` 输出 AST JSON 再由 `adapters/python.mjs` 组装 |
| 前端调用链 | 请求前多出 2~3 张代码卡片，按「组件里发请求的函数 → 它 import 的 API 函数 → HTTP 请求」连起来；`--frontend` 指向前端根目录；静态启发式解析，深度 2、最多 5 张 |
| 红色链路 / 根因 | 请求失败、响应 4xx/5xx、JS 异常按时间排序，最早的失败节点标「根因」并给出排查方向 |

三个关键取舍：
1. 采集是**工具自己**通过 Chrome DevTools Protocol 完成的，不需要 AI 在会话里手工盯。
2. 后端方法图走**静态解析**，所以后端不启动也能画出来；启动后 HTTP 状态/响应体更真实。
3. 跨语言不做"一个解析器通吃"，而是**每语言一个适配器输出统一结构**：语言无关的路由匹配 / 调用树 / 行号切片在 `src/graph-core.mjs`，适配器只负责「源码 → IR」。Java/Spring、Python/FastAPI·Flask 已接入，Node/Go 待加。

## 快速开始（Windows）

前置：Node 22+、本机已有 Chrome/Edge、一个能打开的前端服务。

**1) 启动 apiflow**：双击本目录的 `start.cmd`（等价于 `cd /d <local-path> && node src/server.mjs`）。

**2) 打开工具页**：`http://127.0.0.1:7788`。

**3) 在顶栏选要监听的前端**：点「扫描」会列出本机正在监听、能返回 HTML 的端口（`5174 · 示例前端 · vite` 这种），选中后点「打开并监听」——工具会自己拉起（或复用已开的）带调试端口的 Chrome，打开该地址、注入探针并开始采集。不用再手敲 chrome 命令。

参数（都可省）：

```bat
:: 自动识别语言（按 pom.xml / build.gradle 或 pyproject.toml / manage.py 探测）
node src/server.mjs --backend <local-path>

:: 显式指定语言 + 指定 python 解释器
node src/server.mjs --lang python --python python --backend <local-path>

:: 换端口跑第二份（对比两个项目）
node src/server.mjs --port 7789 --cdp 9223 --lang python --backend <python-root>
```


```bat
node src/server.mjs --backend <local-path> --depth 4
```

`--port 7788`、`--cdp 9222`（浏览器调试端口）、`--backend <java源码目录>`、`--depth <方法展开层数，默认 4>`、`--chrome <chrome.exe 路径>`、`--user-data <浏览器数据目录，默认 %TEMP%/apiflow-chrome>`。

上一次选的地址、浏览器端口与 Chrome 路径会写进 `apiflow.config.json`，下次启动自动沿用。想强制重扫端口就点「扫描」。

- 已经开着同一个地址的标签页会**直接复用**，不会每点一次多开一个；
- 页面里已有探针时**不会强制刷新**，只在没有探针时才 reload 一次来注入。

> 也可以不用顶栏：自己开一个带 `--remote-debugging-port=9222` 的 Chrome，然后用 `curl "http://127.0.0.1:7788/api/connect?target=5174"` 手动连（target 是 URL 子串或 target id 前缀）。

## 图怎么操作

1. 顶部流程条按**依赖关系分列**，不是一根横线：点击 →（可能多个）事件处理 → **并发的 HTTP 请求各自一列上下并列** → 每条请求右侧跟着自己的响应。一眼能看出哪些请求是同一次点击并发出来的，异常为红色。
2. 下方第一个代码卡片是后端 Controller 方法（默认展开），右侧是它在代码里调用的方法。
3. 卡片标题行：`▸/▾` 展开/收起该方法源码；右侧显示 `文件:起始行` 和「N 处调用」。
4. 源码里**被高亮的那几行**就是在调用别的方法，点任意一行会把对应的被调方法卡片展开并连线。
5. 点卡片或节点，右侧面板看文件、行号、方法内调用列表（可直接跳转）。
6. 左侧列表切换不同 trace；异常 trace 会标红。
7. 卡片宽度按最长源码行自适应，单行代码不截断；一行放不下时自动折到下一行，调用线改为纵向汇入被调卡片顶部。
8. **空白处按住拖动 = 平移画布**，**Ctrl + 鼠标滚轮 = 以鼠标位置为中心缩放**（30%–250%，右上角按钮显示当前百分比，点一下复位）；双击空白同时复位平移与缩放；没有滚动条。
9. **拖动方法卡片 = 自由摆放**：按住卡片标题栏拖；流程条上的节点也能直接拖。位置按当前 trace 记住，不想要了就在卡片标题上**双击还原**到自动布局。
10. 右侧「节点详情」面板点 **收起 »** 折成竖条（**节点详情 ◀** 可展开），状态会记住，下次打开保持。
11. 一次点击触发了多个接口时，每个接口是一条**分组标题栏**：`路由 + 根方法 + ×N`，点标题栏或右侧「展开/收起」切换；工具条「展开全部」一次展开。默认只展开第一个接口，其余收起，避免图太长。
12. 每棵方法树按调用深度**向右**排（深度 ≤6），画布不够宽时用平移/缩放看，不再把每层折成一竖条。收起的分组不画响应连线，减少交叉。
13. 点响应节点，右侧「响应体」按 JSON 树展示：对象/数组可点 `▸` 逐层展开，键、字符串、数字、布尔、null 分色；右上「原文」切回未格式化文本。响应体截断上限 20000 字符（超出会标「已截断」）。
14. 每个接口有独立颜色（标题栏与响应节点左侧圆点同色）：响应到分组标题栏的连线走各自的「车道」——从响应下方进入流程条下的空通道、沿左侧走廊下到分组上方间隙再折进标题栏。同接口同色、不同接口错开车道，不会并成一条线，也不穿过卡片。
14. **前端调用链**：请求前按调用关系排几张代码卡片——先是组件里发请求的函数（高亮请求行），再是它用到的 API 函数（如 `dashboardApi.home` → `api/index.ts` 里的 `home: () => http.get(...)`），最后连到 HTTP 请求；点卡片在右侧看完整函数。解析是静态启发式（同文件函数 + `import` 的函数/对象方法，深度 2、最多 5 张）：动态 `import()`、解构重命名、第三方包装层可能断链；`.vue` 为运行时行号，已改为按栈里的函数名定位，基本能对上。
15. **异常定位**：失败节点里最早的那个标红发光、带「根因」徽标，其余失败节点变暗；画布左下角出现一条提示（点它直接选中根因）。详情面板会写「定位：⚡ 根因 / 受影响的异常节点」和「判断」——例如多个接口同时 500 会提示先查后端服务/网关，而不是某条业务代码。
17. **请求流向动效**：监听时每有新请求/响应进来，到该节点的连线上会跑过一次白色虚线高光（约 1.1s、只跑一遍不循环，原有边色不变），数据流动方向更直观；工具条「动效 开/关」可关闭并记忆。

18. **Python（FastAPI / Flask）适配**：`--lang auto|python` 选择适配器；Python 侧用 stdlib `ast` 静态 dump（`src/py/ast_dump.py`，只读源码，不执行）→ `src/adapters/python.mjs` 还原路由与函数调用链。支持 `APIRouter(prefix=)` / `FastAPI()` / `Blueprint`、`include_router(prefix=)` 叠加、from-import 与模块别名解析、方法与函数同名解析；`getattr`/DI/动态路由标为未解析，不做猜测。
16. **接口层失败不追方法链（按接口判断）**：某个接口最近一次响应失败（请求没发出去，或响应 4xx/5xx）时，**只隐藏这个接口自己的方法树**，流程条上它的响应节点标「到此为止」；同一 trace 里已经成功的接口照常展示方法链。左下提示条会说明「失败接口的方法链已隐藏；成功接口仍展示方法树」；想连失败的也一起看，点工具条「显示方法树」。

## 目录

```
apiflow/
├─ src/cdp.mjs         零依赖 CDP 客户端（Node 22 全局 WebSocket）
├─ src/probe.js        注入页面的探针（click / handler / fetch / XHR / error）
├─ src/java-routes.mjs Spring 静态适配器（路由 + 方法调用树 + 完整源码 + MyBatis XML）
├─ src/scan.mjs        扫描本机监听端口、探测可用的前端页面
├─ src/browser.mjs     查找/启动 Chrome、复用标签页、打开目标地址
├─ src/server.mjs      HTTP 服务 + 轨迹聚合
├─ public/             前端页面（原生 JS，无构建）
├─ start.cmd           Windows 启动器（cd /d 到本目录再起服务）
└─ docs/               效果截图
```

## 现在能做什么 / 还不能做什么

能做：
- 80 条 Spring 路由、17 个 Controller、419 个方法的静态索引（example-spring，含 interface）。
- 点击 → HTTP → Controller → 方法内调用 的完整代码图，调用线从具体代码行拉出。
- 每个方法完整源码、调用点行号、异常红色高亮；interface 方法（如 MyBatis Mapper）作为叶子节点展示签名。
- MyBatis Mapper 方法会自动换成 XML 里的 SQL 语句块：卡片带 `XML` 徽标，`<include refid>` 递归展开，详情面板显示语句类型（`<select>` 等）与语句 id。
- 方法图默认展开 4 层（`--depth` 可调），同方法被多处调用时只画一张卡片、多入边。
- 流程条上同一 `method + URL` 的重复请求（轮询/重试）自动折叠成一个节点，标 `×N`，右侧详情列出每次的状态与耗时。折叠后**以最近一次为准**：最后几次恢复了 200 就显示正常（详情会写「之前失败过 N 次，最近一次成功（已复通）」），不会因为最早几次 500 一直挂红。
- 一条 trace 里只要出现过多个接口（点击后并发请求、15s 轮询），每个接口各画一棵方法树，横向对齐、上下堆叠，每棵树根部连到自己那条响应。
- 异常时标出最早失败点（根因）+ 其余失败节点变暗 + 左下角排查提示。
- 失败停在接口层时隐藏后续方法树，只标「到此为止」，可用「显示方法树」查看静态参考。
- 流程条按依赖分层：并发请求并排显示（同列上下），每个请求的响应紧跟其右侧，不再串成一条线。

已知边界：
- interface（Mapper/Service 接口）已解析：命中 MyBatis XML 时展示 SQL 语句块；未命中时展示签名行。
- XML 解析边界：只扫 `resources/mapper/**/*.xml`、按 namespace 最后一段匹配接口名；动态 SQL（`<if>`/`<foreach>` 等）原样展示不渲染；`<include>` 展开后行号可能漂移（显示为 `·`）；`@Select` 等注解 SQL 暂不解析。
- 重载方法只取第一个；反射、动态代理、`@Async`、Feign 跨服务调用会表现为断链。
- 事件处理节点目前只有事件类型（Vue 编译后的 handler 源码行在 CDP 里拿不到 location）。
- 多接口时每棵树独立排版：同一个方法被多个接口调用会各出现一张卡片（暂不合并）。
- 根因判断基于浏览器侧看到的失败顺序（状态码 / 网络错误 / JS 异常），看不到后端内部异常栈。
- 不持久化，关掉即清空（纯审阅工具）。

## 下一步可选

- A. 注解 SQL 与实现类：解析 `@Select`/`@Insert` 等注解 SQL；Service 接口展开 `*Impl` 实现方法。
- B. 真跑后端，把静态线叠加"运行时真实命中"标记（走过的线亮色），并接入后端异常栈做更准的根因。
- C. 补前端红链：Vue 组件定位、未捕获 JS 异常、网络失败重试。
- D. 加语言适配器：Express/NestJS、Flask/FastAPI。
- E. 图交互：按模块过滤、导出图片、端口列表只保留真正的前端服务。
